## TL;DR

- Бэкенд задеплоен и живой: **https://agent-otklikov-api.onrender.com** (Render free,
  засыпает через 15 мин простоя, холодный старт 20–50 сек)
- Flutter-клиент собран под Android, APK установлен и используется на реальном
  телефоне; веб- и Windows-сборки тоже работают
- `pytest -q` (из `server/`) — 41 зелёных, без сети. `flutter analyze` — чисто.
  `flutter test` — 3 зелёных
- Репозиторий: https://github.com/MiG25Foxbat/VC, ветка `master`, коммитим
  напрямую без PR
- Источники вакансий: **trudvsem** и **SuperJob** (реальные, живые). hh.ru и
  avito.ru — запрещены продуктовым решением, не подключать
- Модель: Google Gemini (`gemini-3.1-flash-lite`) через OpenAI-совместимый
  протокол — сменить провайдера/модель можно тремя переменными окружения,
  без правки кода
- **Самое важное для понимания архитектуры**: бэкенд полностью без состояния.
  Профиль кандидата, история подготовленных карточек, статусы
  «отправлено/отказ» — всё живёт только на устройстве клиента
  (`SharedPreferences`). Сервер ничего не хранит дольше TTL кеша (7 суток) и
  ничего не хранит про пользователя вообще.

## HTTP-контракт (5 эндпоинтов)

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/health` | `{"status":"ok"}`, будит сервис |
| POST | `/search` | Ищет по `query` (можно несколько через запятую — это делает **клиент**, N параллельных запросов, сервер не знает про запятые), фильтр по source/region/salary |
| POST | `/extract` | **L3 каскада**: сырой текст вакансии, вставленный вручную → структура (title/company/salary/duties/...) через LLM. Без `LLM_API_KEY` — сразу 400, не притворяется |
| POST | `/prepare` | Тяжёлая: обогащение по ИНН/имени + письмо + brief. 20–60 сек. Клиент шлёт `profile_text` целиком — сервер файл профиля не читает, если текст есть в запросе |
| POST | `/forget` | Стирает запись из кеша по `cache_key` (вызывается после отправки/отказа — локальная копия у клиента остаётся) |

Модель данных (`ResultCard`): `vacancy`, `company`, `owner`, `reviews` (всегда
`[]` — не реализовано), `letter` (`text` + `facts[{claim, source_url}]`),
`brief`, `meta.confidence{company,owner,reviews}`.

## LLM — критично для понимания

- Провайдер полностью через env: `LLM_PROVIDER/LLM_BASE_URL/LLM_MODEL/LLM_API_KEY`.
  Сейчас — Google, `gemini-3.1-flash-lite` (лайт-версия ради лимита; у обычной
  `flash` бесплатный тариф — **20 запросов в сутки на модель**, `/prepare` жрёт
  два вызова за карточку, так что это критично)
- `chat_json()` ретраит 3 раза с бэкоффом на `httpx.ConnectError` — в этой
  дев-песочнице сеть до Google периодически рвётся с пустым исключением,
  ретрай почти всегда лечит. На Render такого не наблюдалось
- **Модель ненадёжно соблюдает промпт-инструкцию** «нет имени в справке →
  пусти письмо пустым» (`write_letter.md`). Поймано вживую: один и тот же
  dossier дважды подряд дал то пустое письмо, то письмо с выдуманным именем
  «Алексей». Раз правило №1 проекта — «модель не придумывает факты», это
  закрыто **кодом**, не только промптом: `_has_addressable_name()` в
  `server/api/main.py` детерминированно обнуляет письмо, если в справке нет
  ни найденного `owner`, ни ИП (у которого имя — часть `company.legal_name`).
  **Не убирать эту проверку** при рефакторинге `/prepare`, иначе фабрикация
  вернётся тихо.

## Обогащение компании

`enrich_company()`: название/ИНН → `dadata.suggest_party` (имя→ИНН, если ИНН
нет) → `dadata.findById.party` (ИНН→полная выписка) → `Company` + `Owner` +
confidence. Только бесплатные методы `suggestions.dadata.ru` — платные
`cleaner.dadata.ru` не трогать никогда (правило проекта). ФИО/пол/телефон —
локально через `phonenumbers` + ручной разбор окончаний отчества, без
дополнительных библиотек.

Известное ограничение, не баг: без ИНН (SuperJob, ручной ввод) резолвинг по
одному только имени компании может попасть на другое юрлицо с похожим
названием («Яндекс» → «АО Яндекс Банк», а не головная структура) — это
поведение DaData, детерминированное, не рандом.

## Flutter-клиент

4 вкладки — Поиск / Лента / Вставить / Очередь; Карточка открывается
навигацией, не таб. Riverpod для состояния, freezed для моделей (см. грабли
про версию — синтаксис `abstract class X with _$X` обязателен в freezed 3.x).

- **Лента**: локальный текстовый фильтр по названию/компании, без повторного
  запроса к серверу
- **Поиск**: можно вводить несколько запросов через запятую — клиент бьёт на
  термины, шлёт параллельно, склеивает результат (`Future.wait`, без дедупа —
  если вакансия попадёт в оба термина, будет дважды)
- **Вставить**: paste текста → `/extract` → экран проверки с редактируемыми
  полями (модель может ошибиться) → `/prepare`
- **Карточка**: если уже готовилась — берётся из локального стора мгновенно,
  без обращения к серверу (сервер мог заснуть или забыть по TTL — неважно).
  Письмо редактируется прямо в `TextField`, правки сохраняются локально.
  Факты — плоским списком под письмом с кликабельной ссылкой, если
  `source_url` похож на URL (в модели данных нет привязки факта к конкретному
  абзацу)
- **Очередь**: список поделён на «не отправлено» / «отправлено» (метки
  ставит сам пользователь после реальной отправки письма — приложение
  ничего не отправляет, это не рассылка, а помощник в написании)
- **Профиль**: редактируется на устройстве, шлётся текстом в каждый
  `/prepare` — `server/profiles/default.yaml` больше не читается на проде,
  используется только для локальной разработки/скриптов

## Грабли инфраструктуры (не наступать повторно)

1. **Render + Python-версия** — без `.python-version` (сейчас `3.12.7`) Render
   ставит новейший Python, под который ещё нет колеса `pydantic-core`
2. **Render ставит зависимости через `pip -r requirements.txt`**, не через uv —
   лок-файл uv (если появится локально) роли не играет
3. **Flutter/Dart версия** — это дев-окружение сидит на Flutter **3.29 / Dart 3.7**,
   не latest stable (3.47/Dart 3.13), потому что `freezed`+`source_gen`+`analyzer`
   на момент работы ещё не понимали новый синтаксис Dart 3.13
   (`DotShorthandPropertyAccess`). Прежде чем апгрейдить Flutter — проверить,
   подтянулась ли экосистема кодогенерации
4. **freezed 3.x** требует `abstract class X with _$X`, не просто `class X with _$X`
   (было в freezed 2.x) — иначе `non_abstract_class_inherits_abstract_member`
5. **Flutter web + CanvasKit** — эта песочница плохо достаёт CDN Google для
   canvaskit.js. Для локального теста веб-сборки: `flutter build web
   --dart-define=FLUTTER_WEB_CANVASKIT_URL=canvaskit/` (использует
   уже забандленную локальную копию). На реальный APK это не влияет
6. **`flutter run -d chrome` не годится** в этой обвязке (пытается сам
   открыть/захватить Chrome) — вместо этого: `flutter build web` + статик-сервер
   + Browser pane на его порт
7. **Android-тулчейн с нуля**: JDK 17 Temurin
   (`C:\Program Files\Eclipse Adoptium\jdk-17.0.20.101-hotspot`), Android SDK
   cmdline-tools + platform-tools + `android-34` + `build-tools;34.0.0`
   (`C:\Users\debil\AppData\Local\Android\Sdk`), NDK `27.0.12077973` (пин в
   `android/app/build.gradle.kts` — `shared_preferences`/`url_launcher` его
   требуют, дефолтный NDK от Flutter старее)
8. **CORS** — без `CORSMiddleware(allow_origins=["*"])` браузерный клиент
   получает молчаливый `Failed to fetch`, сервер при этом честно отвечает
   200 — сообщение об ошибке не долетает без этого миддлвара
9. **Формат ошибок API** — FastAPI `HTTPException` реально отдаёт
   `{"detail": "..."}`, а не задокументированный в BUILD.md
   `{"error":{"message"}}` (тот формат никто и не реализовывал). Клиентский
   `_ensureOk()` разбирает оба варианта
