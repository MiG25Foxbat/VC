# Спецификация сборки

Документ для разработки. Архитектурные обоснования не здесь, здесь только то, что нужно, чтобы писать код.

---

## 1. Переменные окружения

```
LLM_PROVIDER=google            # google | cerebras | groq | openrouter
LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/
LLM_MODEL=gemini-3.6-flash      # gemini-2.5-flash снят с публичного доступа (2026-09)
LLM_API_KEY=

DADATA_TOKEN=                  # подсказки и выписка по организациям
SUPERJOB_APP_ID=               # заголовок X-Api-App-Id

TELEGRAM_API_ID=               # опционально, для каналов
TELEGRAM_API_HASH=

CACHE_TTL_SECONDS=604800       # 7 суток, жёсткий потолок
HTTP_TIMEOUT_SECONDS=15
MAX_CONCURRENT_SOURCES=6
```

Все обращения к модели идут через клиент, совместимый с протоколом OpenAI. Смена провайдера это смена трёх переменных, ни строчки кода.

---

## 2. HTTP-контракт

Один сервис, четыре эндпоинта.

### `GET /health`
Возвращает `{"status": "ok"}`. Нужен для пробуждения сервиса и для пинга по расписанию.

### `POST /search`
Ищет вакансии по запросу. Обогащение не делает, работает быстро.

```json
// запрос
{ "query": "бизнес-ассистент", "region": "Москва",
  "remote": true, "salary_from": 80000, "sources": ["trudvsem", "superjob"] }

// ответ
{ "items": [ { "id", "title", "company_name", "salary",
               "location", "url", "published_at", "source" } ],
  "errors": [ { "source": "superjob", "reason": "timeout" } ] }
```

Источники опрашиваются параллельно. Упавший источник не роняет ответ, он попадает в `errors`.

### `POST /prepare`
Собирает полную карточку по одной вакансии. Это тяжёлая операция, 20 до 60 секунд.

```json
// запрос
{ "vacancy_id": "...", "source": "trudvsem", "profile_id": "default" }

// ответ: объект из раздела 3
```

### `POST /forget`
Удаляет запись из кеша. Вызывается клиентом после отправки письма или при отказе.

```json
{ "cache_key": "..." }   →   { "deleted": true }
```

### Ошибки

Единый формат: `{ "error": { "code", "message", "retryable" } }`.
Коды: `SOURCE_UNAVAILABLE`, `COMPANY_NOT_FOUND`, `LLM_LIMIT`, `TIMEOUT`, `BAD_REQUEST`.
Ничего, кроме `BAD_REQUEST`, не должно приводить к пустому ответу целиком: если не нашлась компания, карточка возвращается без блока `company` и с `confidence.company = 0`.

## 3. Модель данных

```jsonc
{
  "vacancy": { "title", "salary", "employment", "location",
               "url", "published_at", "description", "source" },

  "company": { "legal_name", "inn", "ogrn", "registered_at", "okved",
               "address", "status", "site",
               "finance": [ { "year", "revenue", "profit" } ] },

  "owner":   { "full_name", "role", "source",
               "contacts": { "email", "phone", "telegram", "page" },
               "signals":  [ { "text", "url", "date" } ] },

  "reviews": [ { "source", "rating", "count", "summary", "url" } ],

  "letter":  { "text", "facts": [ { "claim", "source_url" } ] },

  "brief":   { "questions", "likely_test", "salary_range", "red_flags" },

  "meta":    { "confidence": { "company", "owner", "reviews" },
               "cache_key", "expires_at" }
}
```

`confidence` считается по блокам отдельно, значения от 0 до 1. Блок, который не собрался, приходит как `null`, а не как выдуманная заглушка.

## 4. Источники и способ доступа

| Источник | Уровень | Как берём |
|---|---|---|
| Работа России, trudvsem.ru | L0 | Открытое API `opendata.trudvsem.ru/api/v1/vacancies`, ключ не нужен. Отдаёт ИНН работодателя прямо в вакансии. Адаптер: `server/sources/trudvsem.py` |
| SuperJob | L0 | Открытое API `api.superjob.ru/2.0/vacancies/`, заголовок `X-Api-App-Id` (секретный ключ приложения, регистрация на `api.superjob.ru/register`), 120 запросов в минуту с IP. ИНН работодателя не отдаёт — резолвится по названию через DaData. Адаптер: `server/sources/superjob.py` |
| Телеграм-каналы | L0 | Telethon, чтение публичных каналов. Разбирается текст поста |
| Сайты с разметкой JobPosting | L1 | `<script type="application/ld+json">`, схема schema.org/JobPosting |
| Остальные | L2 | Селекторы в `sources/config/<name>.yaml` |
| Не читаются иначе | L3 | Текст страницы в модель, ответ по схеме |

Начинать строго с trudvsem. Он один даёт достаточно данных, чтобы проверить всю цепочку до письма.

## 4.1 Обогащение компании

Цепочка: название из вакансии → ИНН → выписка → сайт и контакты.

Используются ровно два метода DaData, оба на `suggestions.dadata.ru`, оба входят в бесплатный лимит 10 000 запросов в сутки:

| Шаг | Метод | Эндпоинт |
|---|---|---|
| Название → ИНН | Подсказки по организациям | `POST https://suggestions.dadata.ru/suggestions/api/4_1/rs/suggest/party` |
| ИНН → карточка | Организация по ИНН | `POST https://suggestions.dadata.ru/suggestions/api/4_1/rs/findById/party` |

`findById/party` отдаёт руководителя, учредителей, адрес, ОКВЭД, статус, систему налогообложения, финансовые показатели и, если они есть в базе, телефоны, почту и сайт.

Ограничения обоих: 30 запросов в секунду с одного IP, до 300 символов в запросе.

**Платные методы DaData не использовать.** Всё, что живёт на `cleaner.dadata.ru`, тарифицируется по 20 копеек за запись: разбор ФИО, проверка телефона, проверка email. Их функции закрываются локально:

| Задача | Чем вместо DaData |
|---|---|
| Разбить и просклонять ФИО из выписки, определить пол | библиотека `petrovich`, пол по окончанию отчества |
| Регион, оператор и часовой пояс по номеру | библиотека `phonenumbers` |
| Отличить личную почту от ролевой | список префиксов: info, hr, sales, office, support, mail, job |

Часовой пояс нужен не для красоты: письмо и звонок должны попадать в рабочее время работодателя, а не Москвы.

Ролевой адрес помечается в карточке отдельным флагом. Письмо на `hr@` уходит в общий ящик, это ровно то, чего проект пытается избежать, и клиент должен показывать это явно.

## 5. Промпты

Промпты живут в `server/llm/prompts/` отдельными файлами, а не в коде. Менять их можно без деплоя логики.

### 5.1 Извлечение вакансии, `extract_vacancy.md`

```
Ты извлекаешь структуру из текста вакансии.

Верни строго JSON по схеме, без markdown и без пояснений:
{ "title": str, "salary_from": int|null, "salary_to": int|null,
  "currency": str|null, "employment": str|null, "remote": bool|null,
  "location": str|null, "company_name": str|null,
  "duties": [str], "requirements": [str], "conditions": [str] }

Правила:
- Переноси только то, что есть в тексте. Ничего не достраивай.
- Зарплату приводи к числу в рублях в месяц. "от 100к" это 100000.
- Если поля в тексте нет, ставь null или пустой массив.
- duties, requirements и conditions разбивай на короткие пункты
  своими словами, но без добавления смысла.

ТЕКСТ ВАКАНСИИ:
{{raw_text}}
```

### 5.2 Сжатие досье, `compress_dossier.md`

```
Ты готовишь справку о работодателе для человека, который собирается
ему написать.

На входе сырые данные из разных источников. Каждый кусок помечен
источником и ссылкой.

Верни строго JSON:
{ "summary": str,
  "signals": [ { "text": str, "source_url": str } ],
  "hypothesis": str }

Правила:
- summary: три-четыре предложения о том, чем компания занимается
  и в каком она состоянии. Только из переданного.
- signals: до пяти фактов, которые полезны в письме. У каждого
  обязательна ссылка на источник из входных данных.
  Факт без источника не включать вообще.
- hypothesis: одно предложение о том, зачем компании сейчас нужен
  этот человек. Это единственное место, где допустим вывод,
  и он должен опираться на перечисленные signals.
- Если данных мало, верни меньше сигналов. Не восполняй пробелы
  общими словами про отрасль.

ДАННЫЕ:
{{sources_block}}
```

### 5.3 Сопроводительное письмо, `write_letter.md`

Главный промпт. Качество продукта это он.

```
Ты пишешь сопроводительное письмо от лица кандидата напрямую
владельцу или руководителю компании, минуя отдел кадров.

Верни строго JSON:
{ "text": str, "facts": [ { "claim": str, "source_url": str } ] }

Структура письма:
1. Обращение по имени. Если имени нет, письмо не пишется,
   вместо текста верни пустую строку.
2. Одно конкретное наблюдение о его бизнесе, взятое из справки.
   Не комплимент. Факт, который видно только если реально смотрел.
3. Гипотеза о том, что сейчас съедает его время, и один факт
   из опыта кандидата с цифрой, который бьётся с этой гипотезой.
4. Три пункта, которые кандидат снимет с него в первые две недели.
   Конкретные задачи, а не качества.
5. Предложение сделать небольшое тестовое.
6. Подпись именем и контактом.

Жёсткие правила:
- Не более 1200 знаков.
- Каждое утверждение о компании или человеке должно быть
  в массиве facts со ссылкой из справки. Утверждение,
  для которого нет источника, писать запрещено.
- Запрещённые обороты: "ответственная", "коммуникабельная",
  "стрессоустойчивая", "хочу развиваться в вашей компании",
  "рассмотрите моё резюме", "быстро обучаюсь".
- Не приписывать кандидату опыт, которого нет в его профиле.
- Писать простым языком. Без длинных тире, без канцелярита,
  без вылизанных формулировок.
- Если справка бедная, пиши короче. Выдумывать нельзя.

ПРОФИЛЬ КАНДИДАТА:
{{profile}}

ВАКАНСИЯ:
{{vacancy}}

СПРАВКА О РАБОТОДАТЕЛЕ:
{{dossier}}
```

### 5.4 Разбор вакансии, `write_brief.md`

```
Ты готовишь кандидата к разговору по этой вакансии.

Верни строго JSON:
{ "questions": [str], "likely_test": str, "salary_range": str,
  "red_flags": [str] }

- questions: пять вопросов, которые вероятно зададут именно
  на этой позиции у этого работодателя.
- likely_test: какое тестовое задание тут обычно дают.
- salary_range: вилка по рынку для этой роли и формата,
  с оговоркой, что это оценка.
- red_flags: на что посмотреть, чтобы не вляпаться. Опирайся
  на отзывы и состояние компании из справки. Если поводов
  нет, верни пустой массив, не выдумывай.

Гарантий трудоустройства не давать ни в какой форме.

ВАКАНСИЯ:
{{vacancy}}

СПРАВКА:
{{dossier}}
```

## 6. Профиль кандидата

Лежит в `server/profiles/default.yaml`, в git не коммитится. Формат:

```yaml
name:
contacts: { telegram:, email:, phone: }
location:
format: удалённо, около 35 часов в неделю
languages: [ русский родной, английский B2 ]
skills:
  automation: [ ... ]
  operations: [ ... ]
achievements:
  - text: собрала базу на 30000 контактов парсингом
    number: 30000
  - text: настроила отбор до 2000 человек в день
    number: 2000
experience:
  - role:
    org:
    period:
    points: [ ... ]
```

Промпт письма получает этот файл целиком как `{{profile}}`. Ничего сверх него о кандидате модель писать не должна.

## 7. Шаги сборки и критерии готовности

**Шаг 1. Источник.** Скрипт, который по запросу отдаёт список вакансий из trudvsem в JSON.
Готово, когда: тест на фикстуре проходит без сети, поиск по слову «ассистент» возвращает не меньше двадцати живых вакансий, в каждой есть ссылка и ИНН работодателя.

**Шаг 2. Обогащение.** По ИНН собирается карточка компании и руководителя.
Готово, когда: на выборке из десяти компаний блок `company` собрался минимум в восьми, `owner.full_name` минимум в шести, и ни разу не подставилось имя, которого нет в выписке.

**Шаг 3. Письмо.** Генерация письма и справки по промптам выше.
Готово, когда: двадцать писем прочитаны глазами, ни в одном нет факта без источника, ни одно не содержит запрещённых оборотов, и они отличаются друг от друга по существу, а не только названием компании.

**Шаг 4. API.** FastAPI, четыре эндпоинта, кеш в памяти с TTL, деплой на Render.
Готово, когда: холодный старт отрабатывает, `/prepare` укладывается в 60 секунд, `/forget` реально стирает, упавший источник не роняет ответ.

**Шаг 5. Клиент.** Четыре экрана: поиск, лента, карточка с письмом и редактором, очередь отправки.
Готово, когда: приложение переживает засыпание сервера без потери подготовленных писем, минута ожидания показана внятно, рядом с каждым абзацем письма видно источник факта.

## 8. Фикстуры

`tests/fixtures/` содержит сохранённые ответы и страницы. Правила:

- Любой парсер тестируется на фикстуре, сеть в тестах не трогается.
- Из фикстур вычищаются телефоны, почты и ФИО реальных людей перед коммитом.
- Новый источник без фикстуры не принимается.
