# Добавление источника вакансий

Процедура одинаковая для любого источника. Не пропускать шаги, порядок важен.

## Шаг 1. Определить уровень каскада

Проверять именно в этом порядке, останавливаться на первом, который сработал.

- **L0.** У источника есть документированное API. Проверить документацию, найти метод поиска вакансий, выяснить нужен ли ключ и какие лимиты. Если API есть, остальные уровни не рассматривать.
- **L1.** Скачать одну страницу вакансии и поискать в HTML `<script type="application/ld+json">` со схемой `JobPosting`. Если она есть, используется общий парсер разметки, свой код не пишется вообще.
- **L2.** Разметки нет. Определить селекторы вручную и положить их в `server/sources/config/<name>.yaml`. Код не трогать.
- **L3.** Структуру выделить не удалось. Текст страницы уходит в модель по промпту `extract_vacancy.md`.

Записать выбранный уровень и причину в шапку файла конфига или адаптера.

## Шаг 2. Сохранить фикстуру

До написания кода. Скачать один ответ API или одну страницу списка и одну страницу вакансии, положить в `tests/fixtures/<name>/`.

Перед сохранением вычистить из фикстуры телефоны, почты и ФИО реальных людей. Заменить на очевидные заглушки.

## Шаг 3. Написать адаптер

Адаптер обязан реализовать общий интерфейс: принять поисковый запрос, вернуть список объектов `vacancy` из раздела 3 файла `docs/BUILD.md`.

Требования:

- Асинхронный, на httpx, с таймаутом из `HTTP_TIMEOUT_SECONDS`.
- Разбор HTML только через selectolax.
- Своё исключение при недоступности источника, чтобы вызывающий положил его в `errors`, а не уронил весь ответ.
- Никакого headless-браузера. Если источник без JS не читается, он не подключается, и это нормальный исход.

## Шаг 4. Тест на фикстуре

Тест не должен ходить в сеть. Проверять минимум:

- Разбирается нужное число вакансий.
- У каждой заполнены title, url и source.
- Пустой или битый ответ источника не роняет парсер, а возвращает пустой список.

## Шаг 5. Проверка живьём

Один запуск по настоящему источнику. Убедиться, что вакансии свежие и ссылки открываются. Сравнить количество с тем, что видно на сайте глазами.

## Шаг 6. Зарегистрировать источник

Добавить имя в список доступных источников API и в таблицу раздела 4 файла `docs/BUILD.md`, с указанием уровня и способа доступа.

## Чего делать нельзя

- Подключать avito.ru.
- Обходить защиту от автоматического доступа (капчу, блокировку по частоте запросов и
  т.п.). Если источник закрывается, он просто не подключается. **Единственное
  зафиксированное исключение — hh.ru** (`server/sources/hh.py`): читает HTML страницы
  поиска в обход `robots.txt`, подключено 2026-09-24 по прямому запросу продукта,
  осознанно, с пониманием рисков (бан по IP, недокументированная и нестабильная схема).
  Это не прецедент — для любого следующего источника правило снова действует
  без исключений, если продукт не примет для него такое же явное решение.
- Писать селекторы в коде вместо конфига на уровне L2.
- Принимать источник без фикстуры.
